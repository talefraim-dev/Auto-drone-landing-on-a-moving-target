# Agent 2 Catch-up Descent Fix

העדכון מתקן את מצב ה־deadlock שבו Agent 2 ביקש ירידה חיובית, אך
`HOLD_PREDICTIVE_CATCHUP` איפס את פקודת ה־Z ואת רצף ה־Landing Lock בכל צעד.

## ההתנהגות החדשה

- Catch-up נשאר וטו מלא כאשר המטרה אינה LIVE/מאומתת, כאשר הזהות חלשה,
  כאשר התחזית בורחת ממרכז התמונה, כאשר תנועת התמונה מתבדרת, או כאשר
  מדידת התנועה נפסלה בגלל Pitch/Roll/Yaw.
- כאשר המטרה LIVE, מאומתת, ממורכזת ויציבה בתמונה, Agent 2 רשאי לצבור
  Landing Lock גם בזמן שה־catch-up האופקי עדיין פעיל.
- לאחר שני צעדים בטוחים רצופים מותרת ירידה רכה עד `0.28 m/s`.
- מתחת לגובה יחסי של `1.0 m` הירידה הרכה מוגבלת ל־`0.12 m/s`.
- פקודת הגישור אינה מאפסת עוד את ה־Z מיד לאחר פעימת הבקרה. היא מרעננת רק
  את פקודת ה־Z שכבר עברה את ה־gate ואת שכבת הבטיחות, עד `0.35 m/s`.
- טיפוס reacquire שלילי אינו נשמר על ידי הגישור.
- Collision, emergency, Down-LiDAR block ו־Pitch/Roll חריפים ממשיכים
  לגבור על פקודת הירידה.

## מה אמור להופיע בדיאגנוסטיקה

במצב דומה לצילום שסופק:

1. `ALIGN_LOCK_PENDING_SOFT_CATCHUP` עם `LOCK_PENDING(1/2)`.
2. בצעד הבטוח הבא: `DESCEND_SOFT_CATCHUP_LOCK_ACQUIRED`.
3. `applied_vz_mps` יהיה חיובי אך לא יעלה על `0.28`.
4. `bridge_vz` לא יעלה על ה־Z שאושר בפועל, ובכל מקרה לא על `0.35`.
5. קרוב למשטח, cap הירידה יהיה `0.12`.

אם התחזית מתחילה להתבדר או שה־LIVE match אובד, המצב חוזר מיד ל־
`HOLD_PREDICTIVE_CATCHUP`/מצב visual-gap וה־Z חוזר לאפס.

## גבולות הוולידציה

הקוד עבר קומפילציה, בדיקות state-machine, בדיקות command bridge, בדיקות
LiDAR/safety, ובדיקות hash של רכיבי הליבה. לא בוצעה טיסת AirSim חיה בסביבת
הבדיקה, ולכן יש להריץ תחילה `Run_diag.py` לפני אימון נוסף.
